# AlphaMe

Compress, batch-process and temporarily host audio. Node.js + Express backend, FFmpeg/FFprobe encoding, Tailwind CSS v4 + vanilla ES-module frontend (dark UI, English).

## Features
- Upload many files or import links: direct audio URLs, M3U/M3U8 playlists, YouTube / YouTube Music public or unlisted videos and playlists (via yt-dlp).
- **Auto (default)**: picks the target per file (lossless → high-quality VBR, 320k → 192k, 256k → 160k, ~192k → 128k, small MP3s kept as is). Other profiles: Best (VBR ~V0), Balanced (192 kbps), Smallest (96 kbps), Custom (format MP3/M4A/Opus/OGG, bitrate 320–96, sample rate, channels, CBR/VBR).
- Analyzes each file first; shows original vs new size and % saved. Never raises the bitrate of a lossy file; MP3s already within target (or that would grow) are kept untouched. ID3 tags and cover art are preserved when possible.
- Tag editor on every finished file (title, artist, album, year, genre): rewrites the tags without re-encoding and keeps the cover art. A trailing "- Topic" in the artist (YouTube Music auto-generated channels) is removed automatically.
- Queue with limited concurrency, per-file and batch progress, cancel, retry, clear, individual download, ZIP of all results.
- Optional temporary direct link (`/f/<id>/<name>`): Range requests, correct Content-Type, `Access-Control-Allow-Origin: *`.
- Everything (jobs, files, links) is deleted after `TTL_MINUTES` (default 60), also on failure; the work dir is wiped on every start/stop.
- Large files are streamed to disk (never buffered in RAM); size limit, extension/ffprobe validation, safe filenames, SSRF protection for URL imports, jobs isolated per browser.

## Structure
```
src/config.js   environment and constants
src/utils.js    ids, filenames, file helpers
src/net.js      SSRF-safe fetch
src/media.js    ffprobe analysis, profiles, FFmpeg encoding
src/sources.js  direct-URL and yt-dlp importers
src/jobs.js     queue, job lifecycle, cleanup
src/server.js   HTTP API and static frontend
web/            frontend source: index.html, styles.css (Tailwind), js/ (ES modules)
public/         generated by `npm run build`, served by Express (git-ignored)
scripts/        build, checks and end-to-end tests
```

## Run locally
Requires Node 20+, `ffmpeg`, `ffprobe` (and `yt-dlp` for YouTube).
```
npm install
npm run build    # copies web/ and compiles Tailwind into public/
npm start        # http://localhost:3000 (builds automatically if public/ is missing)
npm test         # end-to-end tests with real FFmpeg
npm run format   # Prettier
```

## Deploy on Railway (recommended)
1. Push this folder to GitHub → Railway → New Project → Deploy from repo. `railway.json` + `Dockerfile` are detected automatically (installs FFmpeg and yt-dlp).
2. Optional: set variables from `.env.example`. Health check: `/health`.
3. No volume needed: storage is ephemeral by design.

Vercel: FFmpeg jobs do not fit its execution limits, so host the backend on Railway. If you want the static UI on Vercel, use build command `npm run build`, output directory `public`, set `window.ALPHAME_API` in `web/config.js` to the Railway URL and set `CORS_ORIGIN` on Railway to the Vercel origin. (Audio previews and downloads use the API URL, so everything keeps working.)

## Sources and limits (honest notes)
- **Sources**: YouTube links work for public/unlisted items. Public Spotify playlists are supported (metadata via spotifyscraper; audio resolved via YouTube search). Private playlists are not supported.
- YouTube downloading depends on yt-dlp and may be blocked from some datacenter IPs; keep yt-dlp updated (rebuild the image). Make sure you have the right to download and convert the content.
- **Hosting**: temporary links are served from the app's own disk (free, no third party). The links die after the TTL or on redeploy/restart. Cloudflare R2 (10 GB/month free storage, no egress fees, but requires an account and card) would be the option for longer-lived storage; it is deliberately not included because nothing may be stored permanently without explicit consent.
- Recommended Railway resources: 1 vCPU/512 MB runs `CONCURRENCY=1–2`; disk usage ≈ file sizes × concurrent jobs.

## Config
See `.env.example`. API (all need `x-client-id` header): `POST /api/upload`, `POST /api/import`, `GET /api/jobs`, `POST /api/jobs/:id/{cancel,retry,host}`, `DELETE /api/jobs/:id`, `GET /api/zip`, `GET /health`.
